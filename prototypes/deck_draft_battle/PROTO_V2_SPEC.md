## 0. v1에서 무엇이 바뀌나

v1은 논의가 진행되기 전에 만들어져 확정 방향과 어긋나 있다.

| 축 | v1 (현재 코드) | v2 (이 스펙) |
|---|---|---|
| 편성 자원 | 총 횟수제 (`PLAYS`) | **코스트 예산제** |
| 배치 위치 | 없음 (세로 컬럼 자동 정렬) | **3×3 = 9칸 그리드, 1칸 1유닛** |
| 핸드 개선 | 없음 | **버리기 (횟수 제한)** |
| 병사 카드 | 1종 | **코스트 티어 3종** |
| 카드 타입 | 병사 / 강화 | + **전술 주문 · 군단 오라 · 조건 발동** |
| 상시 계층 | 없음 | **조커 (슬롯 제한)** |
| 유닛 태그 | 없음 | **종족·직업 태그** (조커 조건의 훅) |
| 덱 편집 | 추가만 | 추가 + **제거** |

## 1. 검증 질문

v1의 질문("핸드에서 N장을 배분하는 결정이 재밌는가")은 총횟수제 전제라 폐기한다. v2는 아래를 묻는다.

1. **예산 배낭 퍼즐이 재밌는가** — 공개된 적을 보고 예산을 어디에 쓸지 고르는 결정에 손맛이 있는가
2. **이중 제약(예산 상한 + 9칸 상한)이 몰빵/물량 선택을 살리는가** — 칸이 차면 남는 예산이 강화로 밀리는 압력이 실제로 느껴지는가
3. **조커 엔진이 "폭주"를 만드는가** — 조커 두세 개가 맞물렸을 때 전투가 눈에 띄게 터지는가, 아니면 그냥 스탯 조금 오른 느낌인가
4. **어떤 매개가 실제로 재밌는가** — 처치·사망·상태이상·소환·강화이동·골드 중 무엇이 살아남는가 (§4)
5. **"버리기"가 상점 리롤보다 나은 손맛인가** — 내 덱을 파는 감각이 성립하는가

판정: **PROCEED / PIVOT / KILL** + **조커 매개 범위 확정**

## 2. 라운드 루프

```
[준비] 적 공개 → 드로우 → 예산 안에서 그리드 배치 (+버리기) → 전투 시작
   ↓          (조커는 상시 발동 — 준비/전투 내내 켜져 있음)
[전투] 오토배틀, 개입 없음. 조커·조건발동이 자동으로 터짐
   ↓
[결과] 승/패 판정 · 전장 초기화 · 낸 카드 전부 덱 회수
   ↓
[편성] 카드 추가/제거 + 조커 획득/교체 → 다음 준비
```

## 3. 준비 단계

### 화면 구성
- 적 편성 **완전 공개** (종류·수·스탯·태그)
- **남은 예산 / 총 예산** 상시 표시
- 3×3 아군 그리드
- 핸드 (장수 제한 없음 — 배치 제한은 예산뿐)
- **보유 조커 목록** (효과 전문 노출)
- 버리기 남은 횟수

### 배치 규칙

- **아군 판 = 3×3, 9칸. 1칸에 1유닛.**
  - 근거: 매 전투 초기화되는 판에서 칸 누적까지 허용하면 "칸 상한"이라는 제약이 사라진다. 1칸 1유닛일 때만 *칸이 다 찼는데 예산이 남는* 상황이 생기고, 그 잉여가 강화로 밀리면서 물량 빌드가 자연히 몰빵 쪽으로 전환된다. 이 압력이 예산 제약과 별개 축으로 작동하는 것이 v2의 핵심 검증 대상이다.
- **병사 카드** → 빈 칸에 드롭. 예산 차감.
- **시한부 강화 카드** → 이미 배치된 병사 위에 드롭. 예산 차감. **부착 상한 없음** (몰빵이 어디서 재미없어지는지 보는 게 목적).
- **전술 주문 / 군단 오라 / 조건 발동** → §5.
- 예산을 초과하는 배치는 불가. **남은 예산은 버려진다** (이월 없음).
- **배치 회수 허용** — 되돌리면 예산 환급. 시행착오가 배낭 퍼즐의 일부.
- 병사 0기로는 전투 시작 불가.

### 그리드 → 전장 매핑
- 그리드의 **열이 전열/중열/후열**로 매핑된다. 적과 가까운 열이 먼저 접적한다.
- 사거리·오라 반경 등 정밀한 위치 판정은 v2에서 넣지 않는다. **다만 "인접 칸" 개념은 필요하다** — 강화 이동·전이 계열 조커가 이를 대상 규칙으로 쓴다 (§4).

### 버리기
- 핸드에서 **원하는 카드를 다중 선택** → 버림 더미로 보내고 같은 수만큼 재드로우
- 횟수 제한 (상수). 덱이 소진되면 버림 더미를 셔플해 덱으로.

## 4. 조커 계층 ★ v2 핵심

### 성격 (확정된 것)
- **덱과 분리된 상시 슬롯 계층.** 뽑기에 안 섞이고 항상 켜져 있다.
- **슬롯 제한제** → 무엇을 넣고 뺄지가 커밋 압박.
- **점수 곱연산이 아니다** (우린 점수로 안 깬다). **전투 이벤트의 생산/소비 체인**으로 폭발한다.
- 우리 카드 덱이 단순하므로, 조커가 StS 유물보다 **콤보 깊이를 더 많이 짊어져야 한다.**

### 매개 범위 — 좁히지 않고 전부 넣는다

논의에서 "처치·사망·상태이상·소환·강화이동·골드 중 어디까지"를 정하려 했으나,
**책상에서 고를 문제가 아니라 플레이가 답할 문제**로 판단을 바꾼다.
v2는 **후보 6종을 모두 최소 구현**하고, 플레이테스트로 살아남는 것을 확정한다.

| 매개 | 생산 측 예시 | 소비(페이오프) 측 예시 | 왜 후보인가 |
|---|---|---|---|
| **처치** | 아군이 적을 잡을 때 | 처치 누적으로 전군 강화 | 가장 읽기 쉬운 이벤트. 엔진의 기본 축 |
| **아군 사망** | 아군이 쓰러질 때 | 사망 수만큼 남은 아군 폭주 | **물량 빌드의 페이오프.** 이게 없으면 몰빵만 유리해 대칭이 깨진다 |
| **상태이상** | 스턴·도발·흡혈 등 부여 시 | 상태이상 대상에 추가 효과 | 기존 스킬 어휘를 그대로 재활용 가능 (`skills.csv`) |
| **소환** | 조건 충족 시 유닛 등장 | 소환체 수에 비례하는 효과 | **배치 예산 밖에서 유닛을 늘리는 유일한 매개** → 프리미엄 페이오프 |
| **강화 이동** | 강화를 인접 칸으로 전이·복제 | 강화 개수를 다른 값으로 환전 | 시한부 강화가 배치의 축이므로, 몰빵 빌드 전용 엔진이 된다 |
| **골드** | 전투 중 조건 충족 시 획득 | 골드를 전투 효과로 환전 | 전투와 전투 밖 자원을 잇는 유일한 고리 (§10 골드 구멍과 직결) |

> 소환은 전투 중 유닛 동적 생성이 필요하다 — v1 전투 루프에 없던 요구사항이므로 구현 시 먼저 확인할 것.

### 두 가지 결선 방식을 함께 넣어 비교한다

조커끼리 어떻게 맞물리게 할지도 미결이므로, **양쪽을 다 만들어 놓고 플레이로 고른다.**

**(A) 직결형** — 조커 하나가 `이벤트 → 효과`를 직접 연결.
```
[조커] 아군 사망 시 → 남은 전군 공격력 상승
```
읽기 쉽고 구현이 단순. 대신 조커 N개 = 효과 N개, 깊이가 덧셈으로만 는다.

**(B) 공용 자원 버스형** — 전투 내 공용 스택 자원(가칭 **기세**)을 두고, 생산 조커가 쌓고 페이오프 조커가 소비.
```
[생산] 처치 시 +기세  ┐
[생산] 사망 시 +기세  ┼─▶ 기세 ─┬─▶ [페이오프] 임계마다 전군 버프
[생산] 피격 시 +기세  ┘         ├─▶ [페이오프] 소비해서 소환
                                └─▶ [페이오프] 소비해서 강화 복제
```
생산 3종 × 페이오프 3종 = 9가지 엔진. **조커를 하나 넣을 때마다 조합이 곱으로 늘어난다.**
카드 덱이 단순한 우리 구조에서 깊이를 가장 싸게 얻는 방법. 대신 전투 화면에 자원 게이지 노출이 필요하고, 자동 전투라 결과 예측이 어려워질 수 있다.

- 기세는 **전투 시작 시 0, 전투 종료 시 소멸**한다. 전장이 임시라는 원칙과 일관.
- 기세는 **조커가 없으면 아예 존재하지 않는다** — 조커 계층의 정체성을 선명하게 만든다.

### 설계 원칙 (StS 유물 분석에서)
- **엔진 + 페이오프 페어링** — 반복을 만드는 조각과 반복을 가치로 바꾸는 조각을 짝으로 설계한다.
- **강효과엔 대가** — 고임팩트 조커는 전투 페널티를 동반한다 (보스 유물식). 명백한 정답이 아니라 고민되는 선택이어야 한다.
- **빌드어라운드로 런 정체성** — 종족·직업 태그를 조건의 훅으로 재활용한다 (§6). 얻는 순간 런 방향이 정해지는 조커.
- **정액 스탯 필러는 최소화** — "공격력 조금 상승" 류는 넣지 않는다. 그건 SAP 아류로 가는 길.
- **코스트 조작 조커 = 프리미엄** — 배치 예산이 우리판 StS "에너지"이므로, *예산 확장 / 특정 태그 코스트 할인 / 첫 유닛 무료* 계열이 최상위 빌드어라운드 조각이다. **v2에 반드시 최소 1개 포함**해 이 가설을 본다.

### 획득·게이팅
- 사용 비용이 없으므로 밸런스는 **획득으로만** 잡는다.
- 전투 후 **3택1 제시** + **건너뛰기**.
- **보스급 3택1에는 단점형(강효과+페널티)을 섞는다.**
- 슬롯이 꽉 차면 **교체 여부를 묻는다** — 무엇을 버릴지가 커밋 압박의 실체.
- **슬롯 확장 자체가 성장 축.**

### 최소 카탈로그 구성 요건
전부 만들 필요는 없고, 아래가 한 번씩 들어가면 검증이 성립한다.
- 매개 6종 각각 **생산 측 1개 + 소비 측 1개**
- 직결형(A)과 버스형(B) **양쪽**
- **코스트 조작 조커** 최소 1개
- **단점형(강효과+대가)** 최소 1개
- **태그 빌드어라운드** 최소 1개

## 5. 카드 타입

**병사** — 코스트 티어 3종 (저/중/고). 코스트가 클수록 강하다.
> 코스트 티어가 없으면 예산제가 총횟수제와 같아져 검증이 성립하지 않는다. 파워 티어를 살리려고 예산제를 택했으므로 최소 3종은 필요.

**시한부 강화** — 공격/체력/방어/공속 (v1 유지) + **키워드형 최소 1~2종** (다단히트·보호막·처형·도발·흡혈 중).
> 카드 타입을 늘리기보다 강화 다양화가 가장 싼 깊이 추가라는 것이 리서치 결론. 키워드형은 상태이상 매개 조커의 생산처도 겸한다.

**전술 주문** — 1회성. 배치 시점 또는 전투 개시 순간에 효과가 터진다.

**군단 오라** — 전군 지속 효과.
> 전술 주문 + 군단 오라를 넣으면 "몰빵 vs 물량" 이분법이 **삼각구도**(단일 몰빵 / 물량+군단오라 / 전술 화력)가 되고, 특히 군단 오라가 물량 빌드에 페이오프를 줘서 밸런스가 대칭이 된다.

**조건 발동** — 배치 때 조건을 예약하고, 전투 중 조건 충족 시 **시스템이 자동 발동**한다.
> "카드를 내는 시점"과 "효과가 터지는 시점"을 분리하는 장치. 전투 중 개입 없이도 *중간에 뭔가 터지는 드라마*를 얻는다.
> **수동 타이밍 발동은 절대 넣지 않는다** — 그건 액티브 카드배틀러로의 장르 이탈이다.

모든 카드는 코스트를 가지며, 예산에서 차감된다.

## 6. 종족·직업 태그

- 모든 병사는 **직업 1 + 종족 1** 태그를 가진다. 기존 `src/data/synergies.csv`의 어휘를 그대로 재사용한다.
- **태그는 그 자체로 효과가 없다.** TFT식 임계 시너지는 폐기 확정.
- 태그의 유일한 용도는 **조커 조건의 훅**이다 — "특정 종족 처치 시…", "특정 직업 코스트 할인" 등.
- v2에서는 전 태그를 다 쓸 필요 없이 **소수만** 넣어 훅이 작동하는지만 본다.

## 7. 전투

- 개입 없음. v1의 오토배틀 로직(이동 → 최근접 타겟 → 공격)을 기반으로 확장.
- 그리드 좌표를 전장 시작 좌표로 변환해 스폰.
- **신규 요구사항** — 조커/조건발동이 붙으려면 v1에 없던 것이 필요하다:
  - 전투 이벤트 훅 (처치 / 사망 / 피격 / 공격 / 상태이상 부여)
  - 전투 중 유닛 동적 생성 (소환)
  - 강화 값의 런타임 이동·복제
  - 공용 자원(기세) 카운터 + 화면 표시
- 조커가 터지는 순간은 **눈에 보여야 한다** — 검증 질문 3("폭주가 느껴지는가")이 연출에 달려 있다. 최소한 텍스트 로그나 플래시라도 넣는다.
- 종료 시 전장 초기화. **낸 카드는 전부 덱으로 회수** — 전장에서 죽었는지와 무관.

## 8. 전투 밖 편성

- **카드 추가** — 제시 중 택1 또는 건너뛰기
- **카드 제거** — 덱에서 1장 지우기
  > 버리기가 "덱을 파는" 행위이므로, 덱 압축이 보상받는 구조가 같이 있어야 버리기의 손맛이 검증된다. 둘은 한 쌍이다.
- **조커 획득/교체** — §4 게이팅
- 덱 카드의 영구 강화는 v2 제외 (상점 구조가 미결)

## 9. 구현 메모

> **구현 완료 (2026-07-29).** 아래는 실제 구현 결과 기준으로 갱신된 메모다. 남은 것은 플레이테스트 → 판정.

- 파일: `proto.gd`(루프·UI·이벤트 버스·조커 엔진) · `proto_unit.gd`(유닛·키워드·이벤트 발행) ·
  `proto_data.gd`(**신규** — 카드/조커/웨이브 카탈로그) · `proto.tscn` 유지.
  UI는 v1처럼 **코드 생성**을 유지한다 (씬 편집 비용 절약).
- 조작: 카드 클릭 → 칸 클릭으로 배치. 배치된 칸을 (선택 없이) 클릭하면 회수·환불.
  주문/오라/조건발동은 카드를 한 번 더 클릭하면 즉시 사용. 드래그 대신 클릭-클릭으로 대체했다(프로토 비용 절감).
- 예산·카드 코스트·핸드 장수·버리기 횟수·조커 슬롯 수·웨이브 스펙은 전부 `proto.gd` 상단 const.
- 조커는 `proto_data.gd` 내 딕셔너리 테이블로. 프로토 단계에서 CSV까지 갈 필요 없다.
  카탈로그 현황: 조커 19종 (직결형 A 8 · 버스형 B 7 · 코스트 조작 C 3 · 단점형 2 · 태그 훅 3, 일부 중복 분류),
  카드 24종 (병사 5 / 강화 10 / 주문 4 / 오라 3 / 조건발동 3).
- 프로덕션 코드(`src/`)는 건드리지 않는다. 판정 후 채택되면 그때 `RunState`/배치판을 재설계한다.
  - 주의: 채택 시 직전 커밋의 **4×4 확장은 3×3으로 되돌아간다.**
- 조커 이벤트 훅이 v2 작업량의 대부분이다. 전투 루프에 이벤트 발행부터 넣고 조커를 그 위에 얹는 순서를 권한다.

## 11. 논의 4·5차 반영분 (스펙 작성 이후 확정 → 구현에 포함)

이 스펙을 쓴 뒤 [DESIGN_NOTES.md](DESIGN_NOTES.md) §8·§9가 추가되었고, 아래는 그에 맞춰 구현을 조정한 부분이다.

| 확정 (§8·§9) | 프로토 반영 |
|---|---|
| 골드는 전투에 일절 관여하지 않는다. 예산↔골드 태환 기각 | "예산 → 골드" 전술 주문(현상금) **삭제**. 조커를 통한 골드 획득(`j_bounty`·`j_mom_coin`)은 §9가 명시적으로 허용하므로 유지 |

| 덱 부풀림 비용이 구매 결정의 본체 | 편성 화면 문구로 명시. 카드 제거는 골드 지불로 잠정 구현(경로 미결이므로 임시값) |

**새로 프로토가 답해야 할 질문 (§9에서 추가)**
