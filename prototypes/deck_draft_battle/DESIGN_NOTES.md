> ⚠️ **폐기 문서 (2026-07-29).** 이 논의 기록은 폐기된 **덱빌딩(드로우) 모델** 탐색 단계 산물이다. 현행은 **오토체스 육성 + 전술카드 엔진** 모델이다 → [GAME_DESIGN.md](../../docs/game_design/GAME_DESIGN.md) §12. 아래 내용은 의사결정 히스토리로만 보존한다.

> 확정 기획서(`docs/game_design/`)와 혼동하지 말 것. 프로토타입 검증 후 채택되면 정식 기획으로 승격한다.

## 1. 출발점 — 무엇을 바꾸려 했나

현재 게임은 **"TFT 상점형 추첨 + 영구 4×4 그리드 + 직업·종족 시너지"** 로 확정 진행 중이다
(최근 pull: `fd17dca`, `30c1df0` — 시너지 시스템 + 4×4 확장).

논의의 발단: 이 방식을 **덱빌딩(카드화)** 쪽으로 틀면 어떤가?

핵심 관찰:
- 현재는 사실상 **덱빌딩이 없다.** 핸드 5장이 내 소유 컬렉션이 아니라 **전체 35유닛 풀에서 완전 랜덤 추첨**(TFT 상점 모델). `run_state.gd` → `UnitDB.all_player_units()`.
- 영구 그리드 모델의 약점: 그리드를 한번 채우면 **후반 배치 결정이 소멸**한다(부활 반복). 단, 이번 시너지 도입이 이 약점을 일부 완화.

---

## 2. 두 모델 = 두 장르

| | **A. 그리드 고정 (현재)** | **B. 카드화 회수 (제안)** |
|---|---|---|
| 장르 | 오토체스 / TFT | 덱빌딩 로그라이크 (STS) |
| 영구 자산 | 그리드 군대 | **덱(카드 컬렉션)** |
| 매 전투 결정 | 신규 편입·재배치(점진) | 핸드 드로우→투입(매번 리셋) |
| 시너지 | 그리드 배치로 판정 | 덱 구성으로 판정하면 살릴 수 있음 |

**결론:** 우열이 아니라 "무슨 게임이냐"의 문제. 현재 팀은 A에 투자했고, B로 가면 그 위에서 시너지를
**"덱 구성 기준"** 으로 재해석해야 충돌이 준다. → 확정 전 **프로토타입으로 손맛 검증** 필요.

---

## 3. 프로토타입 확정 스펙 (deck_draft_battle)

검증 질문: **"덱에서 핸드를 뽑아 N장(병사+강화)을 배분해 내는 결정 루프가 재밌는가?"**
특히 **"병사1+강화4 슈퍼유닛 vs 병사5 물량"** 선택에 손맛/깊이가 있는가.

확정한 것:
1. **시너지는 나중.** 프로토에선 뺀다.
2. **전투 구조 = 전투 전 1회 배치.** (실시간 증원·완전 턴제는 기각) → 핸드에서 N장 배분 → 오토배틀 1회 해결.
3. **강화 몰아주기:** 5장을 낸다면 병사1 + 강화4 → 그 병사 하나가 강화 4개를 다 받음.
4. **판 사이 덱 편집:** 전투 후 밖에서 카드 추가/제거로 덱을 꾸린다.
5. **카드 사용 자원 = 총 횟수(발라트로식).** 코스트제 아님. 이유: 몰빵/물량을 대칭으로 만들고, 골드를
   유일 자원으로 유지해 정체성("얼마나 아끼냐")을 선명하게. → 파워 차등이 필요해지면 그때 코스트로 승격.

구현: `proto.gd` + `proto_unit.gd` + `proto.tscn`. 도형 유닛, 근접 오토배틀, 코드 생성 UI.
실행: `proto.tscn` 열고 F6.

## 4. 카드 종류 확장 리서치 (STS / 유희왕 / MTG / 하스 / MonsterTrain)

장르 전반 카드 범주 → 우리 게임 대응:

| 범주 | 우리 대응 | 우선순위 |
|---|---|---|
| 유닛/바디 | 병사 카드 | 있음 |
| 장착/오라(단일) | 강화 카드 | 있음 |
| 일회성 주문 | **전술 주문 카드** | ★ Tier1 |
| 지속 파워(전체) | **군단 오라 카드** | ★ Tier1 |
| 챔피언/영웅 | **챔피언 카드**(덱 1장, 런 내내 성장) | ★ Tier1 |
| 함정/시크릿 | **조건 발동 카드**(트랩 재해석) | ◇ Tier2 |
| 지형/필드/룸 | 지형·포메이션 카드 | ◇ Tier2 |
| 메타 변형(타로/디바인) | 덱 조작 카드/장치 | · Tier3 |
| 저주/상태 | 리스크 카드 | · Tier3 (나중) |

**다음 반복 권고:** `전술 주문` + `군단 오라` 두 개만 추가 → 단조로운 "몰빵 vs 물량"이
**삼각구도**(단일 몰빵 / 물량+군단오라 / 전술 화력)가 되고, 특히 **군단 오라가 물량 빌드에
페이오프를 줘서 밸런스가 대칭**이 된다.

카드 타입 늘리기 전에 **강화 카드 다양화(키워드형: 다단히트/보호막/처형/도발/흡혈)** 가 제일 싼 깊이 추가.

## 5. 핵심 설계 통찰 — "전투 중 개입 없이도 중간에 터지게"

Q: 이런 카드(주문·트랩)를 넣으려면 전투 중간에 카드를 써야 하나?
A: **아니다.** "카드 내는 시점"과 "효과 터지는 시점"을 분리하면 된다.

| 방식 | 효과 발동 | 전투 중 개입 |
|---|---|---|
| 즉시 / 개시 발동 | 배치 즉시 / 전투 시작 순간 | ❌ |
| **조건 발동(트랩)** | 전투 중 조건 충족 시 **자동** | ❌ |
| 수동 발동 | 플레이어가 전투 중 직접 | ✅ |

→ 트랩류를 **"조건 발동"**(예: "첫 아군 사망 시 전군 광폭화")으로 설계하면,
전투 중 개입 없이도 "중간에 뭔가 터지는 드라마"를 얻는다. 결정은 전부 배치 단계로 front-load.
**수동 타이밍 발동만이 전투 중 개입을 강제하며, 그건 액티브 배틀러(클래시로얄)로의 장르 변경**이다.

## 6. 논의 2차 (2026-07-27) — 방향 확정

1차 논의 이후 대화로 아래를 확정. 정식 초안은 [GAME_DESIGN_DECKBUILD_DRAFT.md](../../docs/game_design/GAME_DESIGN_DECKBUILD_DRAFT.md) 에 반영됨.

### 확정 사항
- **방향 = 덱빌딩 스타일(Model 1) 채택.** 누적(Model 2)은 후반 배치결정 소멸이 지병.
- **편성 자원 = 배치 코스트 예산제.** (총횟수제 폐기)
  - 모든 카드에 코스트. 배치는 예산 한도로만 제한, **핸드 장수 제한 없음.**
  - 남는 예산 버림. 핸드 개선은 **"버리기"(선택 버리기 → 덱 재드로우), 횟수 제한.** (상점 리롤 아님 — 덱 압축이 보상됨)
  - 이유: points-buy(턴 템포 아님) → 유닛 파워 티어 살림 + 단일배치 적합 + 완전정보 배낭퍼즐 + 예산=성장축.
- **시너지 = TFT 임계식 폐기 → 조커(유물) 엔진으로 대체.**
  - 조커 = 덱과 분리된 상시 슬롯 계층, **슬롯 제한제**(발라트로식, 커밋 압박).
  - 점수 곱연산 아님(우린 점수로 안 깸) → **전투 이벤트(처치·사망·상태이상·소환·강화) 생산/소비 엔진 체인.**
  - 종족·직업 태그는 조커 조건의 훅으로 재활용.
  - **배치 예산 = 우리판 StS "에너지"** → 코스트 조작 조커가 프리미엄 빌드어라운드.
- **경쟁 지형:** 오토배틀 + 조커엔진 + 드로우덱 3개를 합친 게임은 없음(발라트로/TFT/SAP/Backpack 각자 하나씩 빠짐) = 우리 자리.
- **시작 덱:** 약하고 단순.

### 참고 리서치
- 카드 종류 전수조사(STS/유희왕/MTG/하스/MonsterTrain) → §4.
- StS 유물 심층 분석: 덱분리 상시계층 / 획득 게이팅 / 강효과엔 대가 / 엔진+페이오프 / 빌드어라운드. 우리 조커는 카드덱이 단순한 만큼 **StS 유물보다 콤보 깊이를 더 짊어져야 함.**

## 7. 논의 3차 (2026-07-29) — 전장 구조 확정 + 프로토 v2 스코프

논의 순서를 "조커 매개 먼저"에서 **"전장 구조 → 프로토 검증 → 나머지"** 로 틀었다.
이유: 조커 매개(소환 위치·오라 범위·강화 이동의 "인접")가 전부 전장 구조 위에서만 정의되므로 선행 의존이 있다.

### 확정 사항
- **전장/배치 구조 = 3×3, 9칸 그리드 유지.** (4×4 확장은 누적 모델 전제였으므로 되돌린다)
- **1칸 = 1유닛.** 칸당 누적 없음.
  - 누적 모델에선 셀당 다수 누적이 의미 있었으나, 매 전투 초기화되는 판에서는 그 상한이 사라진다.
  - 1칸 1유닛일 때만 **"칸은 찼는데 예산이 남는"** 상황이 생기고, 잉여 예산이 강화로 밀리며 **물량 빌드가 자연히 몰빵으로 전환**된다. 예산 제약과 다른 축으로 작동하는 이 압력이 v2의 핵심 검증 대상.
- **작업 우선순위 = 빠른 클라이언트 프로토타입.** 상세 카탈로그 설계보다 루프 검증이 먼저.
- **프로토 v2 스코프 = 지금까지 논의한 것 전부** → [PROTO_V2_SPEC.md](PROTO_V2_SPEC.md)
  - 코스트 예산제 · 3×3 배치 · 버리기 · 병사 코스트 티어 · 덱 카드 제거
  - **조커 계층** · 종족직업 태그(조커 훅) · 전술 주문 · 군단 오라 · 조건 발동
  - 제외는 최소한으로: 정밀 사거리/오라 판정, 영구 강화 상점, 챔피언·지형·저주 카드, 보스 메카닉

### 방법론 전환 — 조커 매개는 회의가 아니라 플레이로 정한다
"처치·사망·상태이상·소환·강화이동·골드 중 어디까지"를 논의로 좁히려 했으나 **책상에서 고를 문제가 아니다.**
→ **후보 6종을 모두 최소 구현**하고 플레이로 살아남는 것을 확정한다.
같은 이유로 조커 결선 방식도 **직결형(이벤트→효과)과 공용 자원 버스형(가칭 '기세')을 양쪽 다 만들어** 비교한다.
- 버스형 근거: 생산 N종 × 페이오프 M종 = N×M 엔진. 조커 하나 추가할 때마다 조합이 곱으로 늘어난다.
  카드 덱이 단순한 우리 구조에서 깊이를 가장 싸게 얻는 방법이며, "조커가 StS 유물보다 콤보 깊이를 더 짊어져야 한다"는 요구에 직접 답한다.
- 기세는 전투 시작 0 / 종료 시 소멸(전장이 임시라는 원칙과 일관), **조커가 없으면 아예 존재하지 않는다.**

### 제기된 미해결 구멍
- **골드의 자리가 비었다.** 기존 정체성은 "최소 재화로 클리어 = 얼마나 아끼냐"였는데,
  편성 자원이 골드에서 **배치 코스트 예산**으로 옮겨가면서 골드는 전투 밖(카드·조커 구매)에만 남았다.
  예산은 매 판 리셋되고 남으면 버려지므로 라운드 안에 "아낄 이유"가 없고, 골드는 전투 결과와 연결이 끊긴다.
  → 정체성 문장을 다시 쓸지의 문제. 미결 한 줄로 미룰 항목이 아니다. **→ §8에서 해결.**

## 8. 논의 4차 (2026-07-29) — 골드·런 실패 확정, 정체성 교체

§7에서 제기한 골드 구멍과, 그와 한 쌍인 "전투에서 무엇을 잃는가"를 함께 처리했다.

### 확정 사항
- **골드 = 전투 밖 카드 구매 전용.** 전투에는 일절 관여하지 않는다.
  - 검토했으나 기각: *골드로 이번 전투 예산 구매* / *안 쓴 예산을 골드로 환급*.
  - 기각 사유: 예산↔골드를 태환하면 매 판의 배낭 퍼즐이 "돈을 태울까 말까"라는 단일 축으로 붕괴한다.
    특히 환급은 "남는 예산은 버려진다(풀배치 유도)" 원칙과 정면 충돌하며, 판을 비우는 쪽이 최적해가 되어 배치 퍼즐 자체를 죽인다.
- **패배 = 즉시 런 종료.** 생명·재도전·부활 없음. 이겨도 닳는 축(체력 등) 없음.
  - 아슬아슬한 승리와 압도적 승리는 구분되지 않는다. 닳는 축을 넣으면 "조금씩 손해 보며 버티기"가 생겨 매 판의 완결성이 흐려지므로 의도적으로 뺀다.

### 정체성 문장 교체
기존 **"최소 재화로 클리어할수록 덱 강화가 빨라진다"** 는 폐기한다.
편성 자원이 예산으로 분리되고 예산이 매 판 소멸하므로, 라운드 안에 아낄 대상 자체가 없다.

→ 새 정체성: **"매 판 완벽하게 풀어내라. 한 번 틀리면 끝이다."**
- 매 전투는 **풀배치가 기본**. 결정은 "얼마나 쓸까"가 아니라 **"어디에 배분할까"** 하나로 압축된다.
- 아끼는 축은 골드 쪽으로 이동한다: **무엇을 안 사서 덱을 안 부풀릴 것인가.**
  골드 사용처가 카드 구매 하나뿐이므로 긴장은 "쓰느냐 아끼느냐"가 아니라 **"무엇을 거르느냐"** 에서 나온다.

### 파생된 신규 과제
- **완전 정보와 즉사는 한 쌍이다.** 정보를 다 줬기 때문에 한 번의 패배로 런을 끝내는 것이 정당해진다.
  역으로, 배치 확정 전에 승패를 판단할 수단이 없으면 즉사는 **부당**해진다.
  → **승패 예측 수단(전력 지표 / 시뮬 프리뷰 등)이 선택 기능이 아니라 필수 과제로 승격.**
- **드로우 운으로 런이 끝나는 문제.** 덱빌딩의 유일한 변수(드로우 순서)가 즉사와 만난다.
  현재 완화 장치는 **"버리기"뿐** → 버리기 횟수가 체감 난이도 최상위 레버가 된다.
- **저축이 성립하려면 상점 라인업이 런 진행에 따라 좋아져야 한다.** 상점 구조가 골드 긴장의 성립 조건.
- **덱 압축 밸브.** 카드를 사면 덱이 부푸는데, 되돌릴 수단(카드 제거)의 비용·경로가 미정.

## 9. 논의 5차 (2026-07-29) — 골드 획득처 확정, 이자 도입

### 확정 사항
- **골드 획득처 = 전투 클리어 정액 + 이자 + 조커를 통한 특수 획득.**
- **"이자 시스템 없음 — 재화는 단순 이월" 방침 폐기.** (누적 모델 시절 방침)

### "무엇을 안 살까"라는 긴장의 정체 — 자기 교정
4차에서 이 표현을 썼는데, 두 가지를 뭉뚱그린 것이었고 한쪽은 성립하지 않았다.

- **(성립) 덱 부풀림 비용** — 덱이 커지면 원하는 카드가 손에 덜 온다. 약한 카드는 사는 순간 순손해이고,
  **공짜로 줘도 받지 않는 것이 옳은 카드가 존재**한다. 구매가 자동 행동이 아니라 결정이 되는 진짜 이유는 이것. 이자와 무관하게 작동한다.
- **(성립 안 함) 저축** — "지금 싼 것 말고 모아서 나중에 강한 것"이라 썼으나,
  안 쓴 골드가 가만히 남아있기만 하면 지금 사나 나중에 사나 같아 **아낄 유인이 없다.** 저축은 전략이 되지 못했다.
  → **이자를 넣어야 비로소 이 축이 진짜가 된다.** 이자 도입으로 해소.

### 이자가 만드는 것
- "지금 덱을 보강할까 vs 굴려서 나중에 크게 지를까"가 매 라운드 실제 결정이 된다.
- 저축의 대가도 자연히 존재한다 — **안 사면 덱이 약한 채로 다음 라운드를 맞는다.**
- 결국 **적이 세지는 속도 vs 내 덱이 크는 속도의 레이스**가 골드 축의 본체.

### 주의 — 이자와 즉사의 충돌 가능성
TFT식 이자 굴리기는 **몇 판 지면서 체력으로 지불하는 도박**이다. 우리는 패배 = 런 종료라 **지불 수단이 없다.**
- 시나리오 A: 이자 굴리기가 도박이 아니라 **자살**이 되어 아무도 안 굴린다 → 이자 시스템 사망.
- 시나리오 B: **전투력을 매 판 배치 예산이 공급**하므로 덱이 좀 뒤처져도 당장은 이긴다 → 저축이 안전하게 굴러간다.

B가 유력. 이 경우 **"몇 라운드나 안 사고 버틸 수 있나"** 가 곧 난이도 곡선이 되고,
**적 강화 속도 대비 덱 성장 속도**가 이 게임에서 가장 예민한 밸런스 값이 된다. → 프로토 검증 대상으로 등록.
