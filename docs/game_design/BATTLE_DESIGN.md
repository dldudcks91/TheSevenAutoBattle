## 1. 전투 철학

- 플레이어는 **편성(상점) 단계까지만** 결정한다. 전투가 시작되면 개입 없음.
- 결과는 오직 **배치 + 유닛 육성 + 전술카드**의 결과물이어야 한다.
- 전투는 **완전 정보 기반** — 적 편성은 편성 단계에 공개된다.
- 완전 정보는 즉사 규칙의 전제조건이다 → [GAME_DESIGN.md §10·§11](GAME_DESIGN.md).

---

## 2. 전투 진행 구조

```
[전투 시작]
    ↓
플레이어 유닛·적 유닛 동시 스폰
    ↓
매 프레임: 모든 유닛 AI 동시 실행 (오토배틀)
    ↓
어느 쪽이 전멸하면 전투 종료
    ↓
[결과 처리] 승리 시 보상 지급 → 다음 라운드 / 패배 시 런 종료
```

전투 중 플레이어 입력은 **유닛 클릭 → 정보 확인**뿐. 전투에 영향을 주지 않는다.

## 3. 유닛 AI

### 상태 머신

각 유닛은 매 프레임 아래 상태 중 하나에 있다.

```
IDLE ──→ MOVE ──→ ATTACK
  ↑                  │
  └──────────────────┘
         (쿨타임)

ATTACK / MOVE / IDLE ──→ HURT (피격 시 플래시)
HURT ──→ DEAD
```

### 매 프레임 판단 순서

1. **타겟 유효성 검사** — 타겟이 없거나 죽었으면 가장 가까운 적으로 재탐색
2. **거리 측정** — 타겟까지 거리 계산
3. **행동 결정**
   - 사거리 밖 → MOVE (타겟 방향으로 이동)
   - 사거리 안 + 쿨타임 만료 → ATTACK 시작
   - 사거리 안 + 쿨타임 대기 중 → IDLE 대기
4. **분리 적용** — 아군 유닛과 겹침 보정 (항상)

### 타겟 선택 규칙

- **가장 가까운 적** 단일 타겟
- 타겟이 죽으면 즉시 다음 가장 가까운 적으로 전환
- 특별한 우선순위 없음 (거리 기반 단순 탐색)

> 향후 확장 여지: 직업별 우선 타겟 (e.g., 힐러가 체력 낮은 아군 우선 타겟), 도발 메카닉 등

## 4. 공격 시스템

### 공격 흐름

```
[공격 시작]
    ↓
애니메이션 재생
    ↓
애니메이션 일정 지점 도달 → 피해 적용  ← hit_frame_ratio
    ↓
애니메이션 종료 → 쿨타임(attack_speed) 시작
    ↓
쿨타임 만료 → 다시 공격 가능
```

피해 적용 타이밍(`hit_frame_ratio`)은 유닛마다 다르게 설정할 수 있으며, 애니메이션과 타격감이 일치하도록 조정한다. 구체값은 `src/data/units/units.csv` 참고.

### 근접 vs 원거리

| | 근접 (is_ranged: false) | 원거리 (is_ranged: true) |
|---|---|---|
| 피해 방식 | 타겟에 직접 take_damage() | 발사체 생성 → 도달 시 피해 |
| 유효 거리 체크 | 피해 적용 시점에 재확인 | 발사체가 독립적으로 추적 |

---

## 5. 피해 계산

```
실제 피해 = max(최소 피해, 공격력 - 방어력)
```

- 방어력이 아무리 높아도 최소 피해는 항상 들어간다 — 방어력으로 완전 무효화 불가
- 최소 피해 / 방어력 수치는 데이터 파일 참고

---

## 6. 발사체 시스템

원거리 유닛 전용.

- 발사체는 **호밍(Homing)** — 타겟이 살아있는 동안 방향을 지속 갱신
- 타겟이 죽으면 마지막 방향으로 직진 후 소멸 (빗나감 연출)
- 발사체 속도·충돌 반경은 데이터 파일 참고

---

## 7. 충돌 처리

### 분리(Separation)

- **같은 팀** 유닛끼리만 적용
- 두 유닛의 몸체 반경 합보다 가까우면 서로 밀어냄
- 공격 중에도 항상 적용 → 뭉치는 현상 방지

### 전면 차단(Front Block)

- 이동 방향 정면에 **적** 유닛이 있으면 X축 이동을 차단
- Y축 이동은 허용 → 자연스럽게 옆으로 비켜가는 흐름 형성
- 효과: 일렬 종대로 좁은 공간을 통과하는 대신 측면으로 우회하는 움직임

---

## 8. 배치 시스템

### 그리드 → 전장 매핑

- 아군 배치판은 **3×3 = 9칸이며 한 칸에 한 유닛**만 선다. 판은 **라운드 간 보존**되며, 전투에서 죽은 유닛도 다음 라운드에 부활한다 → [GAME_DESIGN.md §5](GAME_DESIGN.md).
- 전투 시작 시 점유된 칸이 플레이어 **좌측 구역**에 유닛을 자동 스폰. 자유 드래그 배치 없음.
- **열이 전열/중열/후열**로 매핑되어 접적 순서를 결정한다. 위치는 초기 이동 방향·충돌 흐름에 영향을 준다.
- **칸 업그레이드**(§9 훅)는 특정 칸에 영구 효과를 부여하므로 "어느 칸에 두느냐"가 라운드를 넘어 의미를 갖는다.
- **인접 칸** 개념은 강화 이동·전이 계열 전술카드가 대상 규칙으로 사용한다. 정밀한 사거리·오라 반경 판정은 후속 과제.
- 적은 고정 위치에 순서대로 스폰 (편성이 공개되므로 카운터 배치 가능).
- **준비 화면 ↔ 전투 좌표 일치:** 준비 화면 토큰의 글로벌 좌표를 그대로 전투 스폰 좌표로 쓴다. 별도 좌표계로 리매핑하지 않는다 → 화면에서 본 위치 그대로 전투가 시작된다.
- **토큰·유닛 시각 일치:** 핸드 카드 초상화 / 드래그 프리뷰 / 준비 필드 토큰 / 전투 유닛 sprite 가 모두 동일 스케일.

> 향후 지형·엄폐물 도입 시 칸 위치의 전략적 가중치 상승 가능.

### 전투 스탯 적용 순서

전투 시작 시 각 유닛의 최종 스탯은 아래 순서로 합산된다. **셋 다 라운드 간 영구 지속분이며, 매 전투 초기화되는 임시 버프는 없다.**

```
1. 기본 스탯           (units.csv)
2. 유닛 업그레이드      (그 유닛에 누적된 +5 이내의 영구 육성분)
3. 칸 업그레이드        (그 유닛이 선 칸에 부여된 영구 효과)
4. 전술카드 개시 효과   (전투 개시 순간 적용되는 상시 발동분)
```

> **전투 중에 변하는 값은 위 합산에 포함되지 않는다.** 전술카드 발동의 상당수는
> 전투 도중 이벤트로 터지므로 런타임에 스탯을 갱신한다 (§9).

## 9. 전술카드 발동 (전투 중 이벤트)

> 전술카드 엔진 청사진 → [GAME_DESIGN.md §7](GAME_DESIGN.md)
> **폐기:** 이전 모델의 직업·종족 임계 시너지 발동 로직은 사라졌다 → [SYNERGY_DESIGN.md §5](SYNERGY_DESIGN.md).
> 종족·직업 태그는 이제 전술카드 조건이 참조하는 **분류 키**일 뿐 자체 발동이 없다 → [GAME_DESIGN.md §9](GAME_DESIGN.md).

### 발동 시점

- **편성 단계** — 전술카드는 이미 켜져 있다. 코스트 조작 계열은 총 코스트 계산에 즉시 반영된다 → [GAME_DESIGN.md §4](GAME_DESIGN.md).
- **전투 개시 순간** — 개시형 효과가 적용된다.
- **전투 중 상시** — 전술카드는 **전투 이벤트에 반응해 자동으로 터진다.** 배치 시점 스냅샷으로 고정되지 않는다.
- 발동은 전부 **확정 트리거**(처치 시·N타마다·첫 타격 시 등)로 걸린다 — 확률 발동은 결정론 전투(§1)에 어긋나므로 쓰지 않는다.

### 전투가 발행해야 하는 이벤트

전술카드 엔진이 얹히려면 전투 루프가 아래를 이벤트로 내보내야 한다.

| 이벤트 | 발생 시점 |
|---|---|
| 처치 | 아군이 적을 쓰러뜨렸을 때 |
| 아군 사망 | 아군이 쓰러졌을 때 |
| 공격 / 피격 | 타격이 오갈 때 |
| 상태이상 부여 | 스턴·도발·화상 등이 걸릴 때 |
| 소환 | 유닛이 전투 중 새로 등장할 때 |
| 강화 이동 | 부착된 강화가 다른 유닛으로 옮겨가거나 복제될 때 |

### 런타임 요구사항

- **전투 중 유닛 동적 생성** (소환 매개)
- **부착 강화 값의 런타임 이동·복제** (강화 이동 매개)
- **공용 스택 자원 카운터** — 결선 방식이 공용 버스형으로 확정될 경우 → [GAME_DESIGN.md §7](GAME_DESIGN.md)
- **가시성** — 전술카드가 터지는 순간이 화면에 보여야 한다. 자동 전투라 연출이 없으면 "스탯이 조금 오른 느낌"으로 끝난다.

### 적 진영

- 적은 전술카드를 보유하지 않는다. 보스 고유 메카닉은 별도 (§10).
