## 1. 왜 통합했나

기존 유물 시스템과 조커의 정의를 나란히 놓으면 **같은 것**이다.

| 축 | 기존 유물 | 조커 |
|---|---|---|
| 소유 주체 | 플레이어 (유닛 아님) | 플레이어 (덱과 분리) |
| 지속성 | 한 번 얻으면 모든 라운드에 영향 | 상시 발동 |
| 개수 제한 | 고정 슬롯, 가득 차면 교체 | 슬롯 제한제, 가득 차면 교체 |
| 발동 | 전투 시작 시 자동 | 자동, 플레이어 조작 없음 |
| 획득 | 상점/보상 | 전투 후 3택1 + 상점 |

두 계층을 동시에 두면 플레이어는 **"상시 효과 주머니"를 두 개** 관리하게 되고, 어느 쪽에 무엇이 들어가는지가 자의적이 된다.
조커가 이 게임의 정체성(전투 이벤트 엔진)을 짊어지기로 한 이상, 유물은 조커의 하위집합일 뿐이다.

## 2. 조커로 이관된 것

| 기존 유물 개념 | 조커에서의 처리 |
|---|---|
| 플레이어 인벤토리 (고정 슬롯) | 조커 슬롯 |
| 슬롯 가득 시 교체 모달 | 동일 — 무엇을 버릴지가 커밋 압박 |
| 효과 전문 노출 (숨겨진 효과 없음) | 동일 — 완전 정보 원칙 |
| 전투 시작 시 1회 합산 | 확장됨 — 조커는 **전투 중 이벤트에도 반응**한다 |
| `scope` 필드 (ALL_ALLIES / CONDITIONAL / GLOBAL) | 조커 조건 문법으로 흡수. CONDITIONAL의 조건 키는 **종족·직업 태그**가 담당 → [SYNERGY_DESIGN.md](SYNERGY_DESIGN.md) |
| GLOBAL(메타 자원 수정자) | **코스트 조작 조커**로 승격 — 배치 예산이 프리미엄 자원이므로 최상위 빌드어라운드 |

**살릴 만한 설계 자산:** `scope` 3분류는 조커 효과 범위를 정리하는 어휘로 여전히 쓸모 있다.
조커 카탈로그를 짤 때 "전군 / 조건부(태그) / 메타(예산·골드)" 축으로 나누면 커버리지 점검이 쉬워진다.

## 4. 남은 과제 (조커 설계로 이관)

- 조커 슬롯 수·확장 방식
- 동일 조커 중복 보유 허용 여부
- 슬롯 교체 시 환불 유무
- 조커 획득에 골드를 쓰는가 (골드 사용처를 "카드 구매"로 확정했으므로 전투 보상 전용일 수도)
- 조커 등급·세트 효과
