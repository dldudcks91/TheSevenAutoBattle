# TheSevenAutoBattle — 게임 디자인 문서

> 최종 업데이트: 2026-05-07

---

## 1. 게임 개요

- **장르:** 덱빌딩 로그라이크 + 오토배틀 + 시너지 (PvE)
- **플랫폼:** Steam (PC)
- **핵심 한 줄:** "정보는 다 줄게. 그걸로 얼마나 아끼냐가 실력이야."
- **수익모델:** 스팀 단일 구매 (인앱결제 없음)

---

## 2. 핵심 루프

각 라운드는 **3단계**로 진행되며, 각 단계는 별도의 화면(씬)으로 분리된다. 한 단계의 의사결정이 다음 단계의 입력이 되는 구조다.

> **자산 모델**: 플레이어는 **3×3 그리드로 이루어진 영구 군대**를 소유한다. 셀에 병사를 배치하면 런이 끝날 때까지 유지된다. 영구 자산은 골드, 그리드(배치된 병사), 보유 아이템(유물)이다.
> 골드 사용처: **카드 구매** (영웅·강화·아이템 카드 중 선택).

```
[런 시작] 골드 보유, 그리드 비어 있음, 핸드 5장 추첨

[매 라운드]
  1. SHOP 단계
     - 우측: 적 편성 공개
     - 핸드: 랜덤 5장(영웅 / 강화 / 아이템 중 무작위)
     - 영웅 카드를 셀에 드래그 — 같은 종류는 셀당 최대 4명 누적(2×2) 또는 다른 셀로 분산
     - 비-영웅 카드(강화·아이템)는 셀에 드래그하거나 클릭 시 즉시 골드 차감
     - 시너지 패널에 직업·종족 발동 단계가 실시간 표시됨
     - 핸드 좌측 리롤: 카드만 새로 뽑힘, 그리드의 병사는 보존됨
     - 한번 사용한 카드는 핸드에서 사라진다 (셀 우클릭 회수는 같은 라운드 내 리롤 전에만 핸드로 복귀)
     - "전투 시작" 으로 출전 확정 — 그리드 병사 비용 일괄 차감

  2. 전투 단계
     - 오토배틀 진행, 플레이어 개입 없음
     - 전투 후 그리드는 보존 — 다음 라운드 SHOP 진입 시 그대로 유지, 사망자 포함 모두 풀 HP로 부활

  3. 전투 종료
     - 결과·간단 통계 확인 (승/패, 처치 수, 획득 재화 등)
     - 다음 라운드 진입 시 핸드 5장 새로 추첨
     - 다음 라운드 진입 또는 런 종료

[런 종료] 패배 or 보스 클리어 → 모든 자산 초기화
```

**왜 이 모델인가:**
- 그리드 배치는 런 전체에 걸친 **누적 투자** — 어느 셀에 무엇을 올릴지는 런 전반의 방향을 결정
- 카드로 영웅·강화·아이템을 구매 → 골드 긴장감은 카드 선택과 구매 타이밍
- 시너지(직업·종족)는 단순 화력 누적이 아니라 **편성 다각화** 동기를 만든다 → [SYNERGY_DESIGN.md](SYNERGY_DESIGN.md)

**왜 3단계인가:**
- SHOP 단계는 **전술 의사결정** (적 정보 공개 → 카드 구매로 즉각 대응할지 결정)
- 3단계는 라운드 간 호흡과 피드백 (이번 결정이 잘 됐는지 확인)

**핵심 긴장감:**
- 적 구성 확인 후 어떤 카드를 살지 결정 → 정보 기반 투자 딜레마
- 같은 종족·직업으로 시너지를 끌어올릴지, 다양한 직업으로 폭을 넓힐지 → 편성 방향 딜레마
- 그리드 슬롯은 16칸(4×4) — 같은 종류 누적은 화력을 키우고, 다른 종류 분산은 시너지 단계를 키운다 (트레이드오프)
- 영웅·강화·아이템 카드 사이의 자원 딜레마 (즉시 전력 vs 장기 투자)

**런 길이 — 20웨이브 / 4챕터:**
- 한 런은 총 20웨이브 / 4챕터로 구성.
- W5·W10·W15는 챕터별 미니보스, W20이 최종보스. 클리어 시 RUN CLEAR.

> 각 단계 화면의 입출력·전환 계약은 [SCENES.md](SCENES.md) 참고.

## 3. 병사(유닛) 시스템

### 기본 규칙
- **병사는 영구 소유 자산이다.** 구매한 영웅 카드는 그리드에 등록되며 런 전체에서 유지된다.
- **셀당 같은 종류 영웅 최대 4명** 누적 (2×2 사분면). 같은 종류는 다른 셀에 분산도 가능.
- 같은 종류를 여러 셀에 깔아도 시너지 카운트는 종류 단위로 1이다 → [SYNERGY_DESIGN.md §6](SYNERGY_DESIGN.md).
- 셀에 부여된 강화·아이템 카드는 해당 셀의 유닛에게만 적용된다.
- 모든 유닛은 **고정 1스킬**을 가진다. 카드로 스킬을 추가 부여하지 않는다 → [SKILL_DESIGN.md](SKILL_DESIGN.md).

### 시너지 두 축
- 모든 아군 유닛은 **직업(Class) 1** + **종족(Race) 1**을 가진다.
- 그리드 위 유닛 종류 수에 따라 직업·종족 시너지가 단계별로 발동된다.
- 직업 9종 / 종족 5종 / 아군 35유닛 → [SYNERGY_DESIGN.md](SYNERGY_DESIGN.md), [UNIT_DESIGN.md](UNIT_DESIGN.md).

### 에셋
아군 유닛 35종 (minifolks 5종족) + 적 유닛 30종 (minifolks Orcs / Undead / Demons) + 보스 풀 (BigMonsters) 사용.

## 4. 카드 시스템

매 라운드 랜덤 풀에서 **핸드 5장**(`HAND_OFFER_COUNT`, `balance.csv` 의 `hand_offer_count` 키로 조정)이 추첨된다. 카드는 3종류이며 가중치 랜덤으로 섞여 등장한다.

| 카드 종류 | 동작 |
|---|---|
| **영웅 카드 (HERO)** | 그리드 셀에 드래그해 배치. 같은 종류는 셀당 최대 4명 누적. 비용은 "전투 시작" 시 일괄 차감. |
| **강화 카드 (UPGRADE)** | 스탯 지정 강화 — 공격력 / 체력 / 방어력 중 하나가 랜덤 등장. 드래그로 셀에 적용, 해당 셀 유닛에 영구 적용. 셀당 강화 횟수 캡 있음(★ 표시). **그리드에 유닛이 있을 때만 등장**. |
| **아이템 카드 (ITEM)** | 유물 효과. 클릭 시 플레이어 인벤토리에 누적 → [ITEM_DESIGN.md](ITEM_DESIGN.md). |

> 이전 버전의 **스킬 카드(SKILL)는 폐지**되었다. 스킬은 유닛마다 고정 1개로 단순화 → [SKILL_DESIGN.md](SKILL_DESIGN.md).

**핵심 규칙**
- **1회용:** 한 번 셀에 올리거나 클릭으로 소모한 카드는 핸드에서 사라진다.
- **회수:** 그리드 셀 우클릭으로 카드를 빼낼 수 있다 — 같은 라운드 내 리롤 전이라면 핸드로 복귀, 그 외에는 폐기.
- **리롤 (`reroll_cost` g):** 핸드 좌측 버튼. 카드만 다시 뽑는다 — **그리드에 배치된 병사는 그대로 유지**된다.
- **셀 규칙:** 셀에는 1유닛만 배치된다. 같은 종류는 다른 빈 셀로 분산.
- 동일 카드 풀의 중복 등장은 허용 (with replacement).

데이터: 카드 가중치·풀 구성은 `src/economy/run_state.gd` 의 `_roll_hand_offer()` 에서 관리.

## 5. 적 구성 — 3종족 30유닛

| 종족 | 챕터 | 방향성 |
|------|------|--------|
| **Orcs** | 챕터 1 (W1~W3) | 숫자 압박·기마 침투 — 기초 학습 |
| **Undead** | 챕터 2 (W4~W7) | 원거리·부활·디버프 — 메카닉 도입 |
| **Demons** | 챕터 3 (W8~W10) | 화염·매혹·정예 단일 — 종합 압박 + 보스 |

> 종족별 유닛 라인업·카운터 힌트는 [UNIT_DESIGN.md §3](UNIT_DESIGN.md) 참조.
> 웨이브별 학습 의도와 압박 곡선은 [WAVE_DESIGN.md](WAVE_DESIGN.md) 참고.
> 보스 라운드(W10)에는 BigMonsters 풀의 거대 단일 유닛이 등장할 수 있다.

## 6. 밸런스 데이터 관리

경제 수치(골드·보상·카드 가격 등)는 코드가 아닌 CSV에서 관리 — 코드 수정 없이 조정 가능.

| 파일 | 내용 |
|------|------|
| [src/data/balance.csv](../../src/data/balance.csv) | 경제 상수 (시작 골드, 라운드 보상, 리롤 비용 등) |
| [src/data/rounds.csv](../../src/data/rounds.csv) | 웨이브별 적 라인업 |
| [src/data/units/units.csv](../../src/data/units/units.csv) | 유닛 기본 스탯 (아군/적 구분 + 직업·종족 컬럼). 표시명은 `name_key` 컬럼에 번역 키만 둔다. |
| [src/data/items/items.csv](../../src/data/items/items.csv) | 아이템 옵션·가격. 표시명은 `name_key` 컬럼에 번역 키만 둔다. |
| [src/data/synergies.csv](../../src/data/synergies.csv) (예정) | 직업·종족 시너지 단계 임계값 + 단계별 효과 페이로드 |
| [src/data/i18n/text.csv](../../src/data/i18n/text.csv) | 다국어 텍스트 (`keys,ko,en`) — Godot이 자동으로 `text.ko.translation` / `text.en.translation` 생성. 코드에서 `tr(key)`로 사용. |

> 데이터 CSV는 모두 `.import` 가 `importer="keep"` 으로 설정돼 있어 Godot의 csv_translation 임포터를 거치지 않는다 (컬럼명이 로케일로 오인되면 안 되므로). i18n CSV(`src/data/i18n/`)만 csv_translation으로 자동 임포트된다.

## 7. 미결 항목

| 항목 | 상태 |
|------|------|
| 카드 풀 가중치 (HERO / UPGRADE / ITEM) | 미결 — 스킬 카드 폐지에 따른 재배분 필요 |
| 그리드 확장 여부 | ✅ 확정 (2026-05-08) — 4×4 = 16칸으로 확장. 셀당 4명 누적 유지. 적 그리드는 별도(라운드별 자유 설계) |
| 시너지 효과 카탈로그 (직업 9 + 종족 5의 단계별 효과) | 미결 → [SYNERGY_DESIGN.md §9](SYNERGY_DESIGN.md) |
| 9번째 유닛 추가 획득 경로 (휘장 / 보상 / 해금) | 미결 → [SYNERGY_DESIGN.md §9](SYNERGY_DESIGN.md) |
| UPGRADE / ITEM 카드 실효 효과 | 미결 — 현재 클릭 시 골드만 차감하는 더미 |
| 셀 초기화/타입 변경 비용 또는 불가 여부 | 미결 |
| 라운드 간 그리드 영속화 (영구 자산) | 결정 — 그리드는 런 전체 유지. 사망자도 풀 HP로 부활. 비용은 신규 배치분만 차감. 회수는 unpaid entry에만 가능 (paid는 영구 자산). |
| 셀 비우기/판매 (paid entry 처분) | 미결 — 현재 슬라이스는 추가 + 셀 간 스왑만 허용. 환불·셀 비우기는 후속. |
| 사망 페널티 | 결정 — 없음 (전원 풀체력 부활). 향후 변경 시 재논의. |
| 보스 메카닉 | 미결 — W10 보스로 BigMonsters 풀 중 무엇을 쓸지, 호위 구성 어떻게 할지 |
| 웨이브별 적 라인업 (Orcs/Undead/Demons로 재편) | 미결 — [WAVE_DESIGN.md](WAVE_DESIGN.md) 갱신 후 [src/data/rounds.csv](../../src/data/rounds.csv) 재작성 |
| 웨이브별 골드 보상 곡선 | 결정 — `reward_per_round + reward_growth_per_round × wave_index`. 플레이테스트 후 수치 조정. |
| 패배 페널티 구조 | 미결 |
| 적 종족 시너지 도입 시점 | 미결 → [SYNERGY_DESIGN.md §7·9](SYNERGY_DESIGN.md) |
